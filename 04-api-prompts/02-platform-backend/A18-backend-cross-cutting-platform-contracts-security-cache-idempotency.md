## 2. Contract groups to cover

- Response envelope: `{ status, data, metadata }`, error code mapping, pagination metadata.
- AuthN/AuthZ: unauthenticated, wrong role, disabled/suspended user, admin/client boundary, impersonation attribution.
- Validation: DTO enum/date/amount/file/email/tax ID validation and consistent 400/422/409 mapping.
- Idempotency/replay: payment/order/webhook/document/notification/outbox duplicates.
- Rate limit/throttle/abuse boundaries.
- CORS/origin, security headers and gateway path normalization.
- Public HTTP cache and cache-bust behavior for public blog/portfolio/content.
- Correlation/request IDs, structured logs and redaction.
- Maintenance/readiness/degraded dependency behavior.
- Database invariants, optimistic/concurrent updates and transaction rollback.

## 4. Mandatory tests

1. **Envelope and error shape**
   - For at least ten endpoints across auth, users, requests, quotes, projects, payments, media, notifications, content, health, verify success envelope and error envelope.
   - Verify hand-built service `{status,data}` responses are normalized and do not escape transform rules.
2. **Pagination/filter/search contracts**
   - Exercise list endpoints with default, limit, max limit, page beyond range, sort, search, filter, invalid enum and invalid date.
   - Verify metadata is stable and no 500 occurs from invalid query params.
3. **Auth and role boundaries**
   - Unauth, client, admin and impersonated admin attempts for representative endpoints.
   - Wrong-portal login must be 403/appropriate business error, not validation noise.
   - Suspended/disabled users cannot mutate protected resources.
4. **Idempotency and duplicate prevention**
   - Repeat create/update/send/accept/complete operations for quotes, payments, milestones, webhooks, notifications and documents.
   - Verify duplicate charges/documents/outbox rows are blocked or deduplicated.
5. **Payment invariants**
   - Zero/non-positive amount rejection.
   - Reused Razorpay order for different amount rejected.
   - Manual/offline refund ledger behavior.
   - Client cannot unilaterally flip completed payment to disputed.
   - Disputed completed payments remain in revenue KPI until refund per source rule.
6. **Document/tax validation**
   - Invalid GSTIN/PAN rejected.
   - Legal fields blank when unset; internal enums not printed in generated docs.
7. **Media/file safety**
   - SVG/script content rejected even when extension or content-type is spoofed.
   - Private media access denied to project members who are not owners where source requires it.
   - Unsafe files force download when stored/served.
8. **Webhook URL and outbound safety**
   - Reject loopback/link-local/private DNS targets and revalidate before delivery.
   - Test webhook signing/idempotency/replay where safe.
9. **Cache/correlation/logging**
   - Public content cache headers match policy; stale empty public payloads can be cache-busted after reseed.
   - Client-supplied valid `X-Request-ID` is honored; invalid IDs sanitized.
   - Error logs/audit entries redact secrets/tokens.
10. **Maintenance/dependency degraded mode**
   - Health/dependency endpoints report degraded DB/Redis/S3/RabbitMQ state accurately if a controlled degraded environment exists; otherwise record source-anchored expected behavior.

## 5. Negative and abuse probes

- Invalid UUID and non-UUID path params.
- Overlong search/query/body fields.
- Enum casing variations and impossible state transitions.
- Concurrent double-click/double-submit on quote send/payment create/milestone approval.
- Replay webhook with same provider event ID.
- CORS preflight from allowed and disallowed origins.
- Path traversal in media/file/document names.
- Object access with another client’s ID.

## Security addendum — mandatory for this API prompt

Run the relevant checks from [`00-SECURITY-RUNBOOK.md`](../../06-security-prompts/00-SECURITY-RUNBOOK.md) before closing this API/backend prompt.

At minimum, verify:
- Authentication, role authorization and object ownership for every endpoint group, including unauthenticated, client, admin, wrong-role, suspended and impersonated sessions.
- Input validation rejects malicious-looking path/query/body values, invalid enums, oversized fields, tampered IDs and malformed payloads with safe error envelopes.
- Mutating endpoints are protected against CSRF/origin abuse where browser-callable, replay, double-submit, race conditions and idempotency failures.
- Rate limits or practical abuse controls exist for auth, reset/OTP, contact, comments, upload, checkout, webhook and notification endpoints.
- Logs, debug responses, error envelopes, generated artifacts and worker payloads redact tokens, cookies, OTPs, reset links, provider secrets, private URLs and unnecessary PII.
- If this prompt touches payments, webhooks, media, documents, messaging, notifications, exports, seed/reset or system operations, also run the matching `S##` security prompt from `06-security-prompts/`.

Add a `Security findings` section to the prompt result using the security runbook output template. Stop and escalate P0 for auth bypass, cross-user data, token leakage, duplicate charge, unsigned webhook acceptance, unsafe webhook target acceptance, stored XSS or privilege escalation.
