# P15 — Client settings, profile, security, sessions, data export and account deletion

**Priority:** P0  
**Primary role:** authenticated client  
**Scope:** Client account management and security
**Target host:** `https://app.nestlancer.com` (client portal)
**Accounts:** see [`DEMO-ACCOUNTS.md`](../../00-start-here/DEMO-ACCOUNTS.md)


## 0. Demo-production mode for this prompt

This suite is intended for a production-like app with demo data. Execute create/update/delete/status/password/session/payment/media operations when the target object is clearly demo/audit data for this prompt. If the object is not confirmed demo/audit, record the control and stop before final confirmation. Always capture before/after state and audit/network evidence.

## 3. What this prompt must prove
- Profile/security/account pages are deeply walked.
- Password, 2FA and sessions are tested safely.
- Data export and deletion/cancel deletion states are covered.

## 4. Mandatory browser walk
1. Verify settings tabs and redirect aliases.
2. Profile view/edit: name/company/avatar upload/remove/save payload keys/cancel.
3. Account: preferences, data export request/download, deletion request/cancel, confirmations.
4. Security: change password validations, 2FA setup QR/secret/copy/verify/backup/regenerate/disable, sessions, revoke, sign out other devices.
5. Activity: pagination/empty/error; recent profile/security action appears.
6. Second browser context: revoke/terminate and then attempt action.
7. Admin user detail parity in P30.

## 5. Controls and page-in-page units that must be inventoried
- settings tabs

- avatar upload/remove
- data export
- delete account
- cancel deletion
- change password
- enable/verify/disable 2FA
- backup codes
- session revoke
- sign out other devices

## 6. Data and safety fences
Use dedicated audit client. Do not enable 2FA/change password on shared accounts unless recoverable.

## 7. Required evidence
- Screenshot every L1 route and each L2 tab / L3 drawer / L3 modal opened by this prompt.
- Capture Console warnings/errors after load and after each mutation.
- Capture Network rows generated by UI actions only: method, path, status, duration, request keys, response code/message. Redact token/cookie/PII values.
- Capture Storage key names/cookie attributes only when auth, impersonation, download, share, or token handling is relevant.
- Run keyboard-only traversal for the primary flow and verify focus return from every dialog.
- Add mobile evidence at 375px for dense tables, forms, drawers, and danger-zone confirmations.

## 8. Edge states / negative probes
- Wrong current password.
- Sole active session.
- Pending deletion account.
- Mobile danger zone.

## 9. Defects this prompt is designed to catch
- Password change leaves old session active when promised not to.
- Backup codes exposed after leaving page.
- Deletion pending not visible.
- Profile save carries role/status.

## Security addendum — mandatory for this prompt

Run the relevant checks from [`00-SECURITY-RUNBOOK.md`](../../06-security-prompts/00-SECURITY-RUNBOOK.md) before closing this prompt.

At minimum, while executing this UI prompt verify:
- Protected UI/API calls are not accessible anonymously or by the wrong role.
- Demo user A cannot view or mutate demo user B objects by changing IDs, URLs, filters or request bodies.
- All text/query/file/template fields safely handle malicious-looking input without XSS, open redirect, path traversal, stack traces or debug leakage.
- Mutating controls are resistant to CSRF/clickjacking assumptions and have correct confirmation/audit behavior.
- Browser storage, console output, debug panels, generated artifacts and network responses do not leak tokens, cookies, OTPs, reset links, private URLs, provider secrets or unnecessary PII.
- If this prompt touches payments, webhooks, media, documents, messaging, notifications, exports or system operations, also run the matching `S##` security prompt from `06-security-prompts/`.

Add a `Security findings` section to the prompt result using the security runbook output template. Stop and escalate P0 for auth bypass, cross-user data, token leakage, stored XSS, duplicate charge, unsigned webhook acceptance, unsafe webhook target acceptance or impersonation attribution failure.
